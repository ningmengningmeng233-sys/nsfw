# 检索定位：执行协议 v4.8.1

> **何时读取**：进入“检索”“全文搜索”“跨书比较”“基于索引创作”或“文风蒸馏”分支时读取；不要为建库加载本文件。
>
> 本文件是读取范围和授权的单一真相。先完成授权判定，再选择读取级别；用户看到的结果必须能回溯到实际文件和行号。

---

## 0. 读取前置：授权和范围

每次进入本文件流程都先确定：目标小说/作者、任务目的、允许读取层级、授权来源、范围上限和交付格式。读取 `<索引库>/_授权状态.yaml`；不存在或不可解析时只使用当前对话明确授权。授权不跨书、不跨任务、不从索引段落扩展到原文。

完成当前目的即停止，不为了“顺便完整”继续读；无法确定目标书或范围时先询问。

## 一、四级读取层级（硬性规则）

```
用户提问
  ↓
【第1级】只读 YAML 元数据（小说索引 frontmatter + 章节索引文件名）
  ↓ 用户要求"进一步"（定位类原始提问直接进第 2 级）
【第2级】读元数据对应索引文件的对应段落
  ↓ 用户要求"查看全部索引内容"
【第3级】读完整索引文件
  ↓ 用户要求"查看原文"
【第4级】读原文段文件的对应章节（按索引记录的段文件内行号范围）
```

**核心原则：每一级满足用户需求即止；用户要求进一步，才进下一级。不跨级、不扩大范围。**

## 二、第 1 级：读元数据

### 触发条件
用户提问（默认起点）。任何检索类请求都从第 1 级开始。

### 允许操作
- 只读取 `索引库/小说索引/` 下小说索引文件的 **YAML frontmatter**
- 只**列出** `索引库/章节索引/` 下的文件名（文件名本身即元数据：
  `<小说名>-<作者>-第X章~第Y章-NNN-idx.md`，可解析出章节范围与编号）
- 其他内容一律不得查看

### 操作步骤

1. 用 Glob/Grep 列出 `小说索引/` 下所有 `.md` 文件（工具名随宿主环境）
2. 用 Read 只读取每个文件的前 30 行（frontmatter 部分）
3. 从元数据中提取：小说名、作者、章节范围、包含元素、最后索引章节
4. 用 Glob（pattern=`<小说名>-<作者>-*`）扫描 `章节索引/`，
   按文件名列出该小说的全部章节索引（文件名即导航）
5. **显式排序**：按文件名末尾 3 位编号排序，不依赖 Glob 默认排序

### 元数据字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `小说名称` | 是 | 原始名称（可含《》） |
| `作者` | 是 | 用于同名小说区分 |
| `索引类型` | 是 | 小说索引 / 章节索引 |
| `章节范围` | 是 | 如"第1章~第5章" |
| `包含元素` | 是 | 叙事元素标签列表；标签词汇表可由 `tags.custom.yaml` 扩展，详见第二节语义召回 |
| `源文件` | 是 | 段文件相对路径（章节索引） |
| `创建日期` | 是 | YYYY-MM-DD |
| `状态` | 否 | 完成 / 待完善 |
| `最后索引章节` | 否 | 增量索引用（小说索引） |

### 第 1 级输出示例

```
在索引库中找到 1 本小说的索引：

1. 《大奉打更人》- 卖报小郎君 — 章节索引 184 个（第1章 ~ 第125章，含番外）
   - 包含元素：装逼打脸、身份反转、修炼升级、金句、修罗场...

您想查看哪本小说的详细内容？
```

## 三、第 2 级：读索引对应段落

### 触发条件
用户在第 1 级基础上要求 **"进一步"** 查看，如：
- "大奉打更人的爽点有哪些"
- "XX角色的出场章节"
- "XX在第几章"

**定位类问题（如「XX在第几章」「XX角色的出场章节」）是原始提问时**：
完成第 1 级定位后**直接进第 2 级**搜索并交付答案，不必等用户再确认"进一步"。

### 允许操作
读取第 1 级定位到的章节索引文件的**对应段落**（如爽点清单、人物设定、
剧情索引表）——**不是整个索引文件**。
**跨文件检索（v4.5 拷问定稿）**：定位类问题（角色出场章节/伏笔回收/套路分布等
跨段查询）默认**跨该小说全部章节索引** grep——只返回命中章节+小节+行号，
不读取命中内容之外的范围；搜索范围限定该小说前缀（`<小说名>-<作者>-*-idx.md`，
防跨书混入，见第七节），授权与单文件检索同级（定位类豁免当次确认）。

### 操作步骤

1. 根据第 1 级结果，确定该小说章节索引文件集
   （`索引库/章节索引/<小说名>-<作者>-*-idx.md`）
2. 用 Grep **跨文件**搜索用户查询的关键词（单文件搜索仅用于用户指定了具体段时）
3. 只读取匹配行及其上下文（前后 5 行）
4. 回答用户问题，跨文件命中按段编号排序汇总，格式：
   ```
   <关键词> 命中 <N> 处：
   - 第X章（段文件 行a~b）：<索引摘要>
   - 第Y章（段文件 行c~d）：<索引摘要>
   ```

### 语义召回（v4.5 审查新增，精确匹配的补充层）

**触发条件**：精确关键词命中 <3 处，或用户意图是**模糊描述**（如「找一段写母亲离别的
场景」——没有可 grep 的精确词）。

**操作**（仍只读索引，第 2 级范围，不扩大读取）：
1. **标签反向定位**：从「包含元素」标签中找相关标签（如「离别/亲情/回忆杀/虐心」），
   按标签定位候选段——标签词汇表（`templates/包含元素标签词汇表.md`）即联想词源。
   若索引库根目录存在 `tags.custom.yaml`，则自动与内置词汇表合并，同名组以自定义为准。
2. **近义扩展重 grep**：把意图拆成近义词组（如「离别」→ 送别/辞行/离开/远行/分别），
   逐词 grep 候选段
3. **金句/概要素描判断**：对候选段读「金句/名场面」小节与「本段概况」，
   由编排器做语义相关性判断（读摘要，不读原文）
4. **向量语义召回（v4.6 ADR-0004，可选）**：若索引库已构建 `.semantic_index/`
   且启用语义索引（`INDEX_ENABLE_SEMANTIC=1` 运行 `scripts/semantic_index.py`，
   或 `orchestrate.py semantic build --force`），
   可调用 `scripts/semantic_search.py`（或 `orchestrate.py semantic search`）对章节索引块
   做向量相似度检索；命中条目并入本层结果，同样按上方跨文件命中格式输出，并标注
   「语义召回命中（非精确匹配）」。未启用或不存在向量索引时跳过本步，不影响关键词
   召回与标签召回流程。

**交付**：按跨文件命中格式输出，标注来源：
```
「母亲离别的场景」语义召回 2 处（非精确匹配，基于标签+概况/向量判断）：
- 第X章（段文件 行a~b）：<索引摘要>（标签：亲情 | 离别）
- 第Y章（段文件 行c~d）：<索引摘要>（语义召回命中（非精确匹配））
```
**边界**：语义召回命中只是候选，交付时如实标注"基于标签/概况/向量判断"，不冒充精确
命中；用户要确认原文 → 走第 4 级按行号读取。

### 第 2 级输出示例（按上述跨文件命中格式）

```
《大奉打更人》「爽点」相关命中 3 处：

- 第86章（段文件 行320~479）：危机化解 — 神殊被九大法相压制，众人合力唤醒
- 第89章（段文件 行480~720）：实力提升 — 许七安晋升半步武神，一拳轰出蘑菇云
- 第90章（段文件 行721~900）：金句 — "大奉银锣许七安"命名式登场

需要查看哪处的详细原文？
```

（行号为示意，实际须来自索引记录的段文件内行号）

## 四、第 3 级：读全部索引内容

### 触发条件
用户**明确说出**要查看索引文件的全部内容，如：
- "把索引文件的所有内容给我看"
- "查看全部索引"

### 允许操作
读取目标章节索引文件的**完整内容**。

### 安全条款
分卷逐一展示，每展示一个索引文件后询问"是否继续查看下一个"，
防止一次性 dump 所有索引耗尽 tokens。

## 五、第 4 级：读原文对应段落

### 触发条件
用户在第 2 级或第 3 级基础上**明确要求**查看原文，如：
- "第88章的原文是什么"
- "许七安晋升半步武神的那段原文给我看"

### 允许操作
根据索引 frontmatter 的 `源文件`（段文件相对路径）定位段文件，用
Read 工具（起始行 offset、行数 limit）读取**指定片段**。
行号一律为**段文件内行号**（索引记录时已换算）。

### 硬性限制
- 单次读取 **≤ 500 行**
- 只读该章节/片段的行范围，**不得顺带读全文**
- 行号范围必须来自索引记录，不允许用户自行指定行号

### 第 4 级输出示例

```
《大奉打更人》第88章原文（段文件第 150 行 ~ 第 320 行）：

[原文内容]

---
原文位置：《大奉打更人》第88章
段文件：小说原文/大奉打更人-卖报小郎君/大奉打更人-卖报小郎君-第86章~第90章-177.md
段文件内行号：150 ~ 320
索引文件：大奉打更人-卖报小郎君-第86章~第90章-177-idx.md
```

## 六、安全防护

### 6.0 授权粒度（单源真相，对应 SKILL.md 授权机制）

> 适用范围：检索阶段与阶段三创作/文风蒸馏的素材收集——读取操作一律按本表与
> 四级路径执行，不得因"创作需要素材"绕过当次确认。

**总则（v4.5 审查收敛）**：用户**主动明示目的**的高层请求（定位类提问、文风蒸馏
触发），其**完成该目的所需**的读取免逐级确认；豁免**不延伸**——超出该目的范围
（如查看全文、扩大读取范围）仍按本表逐级确认。下表的两条例证均由总则导出，
后续新增能力不再单独枚举豁免，一律先套总则判断。

| 授权项 | 说明 |
|--------|------|
| 读取元数据 | 默认允许 |
| 读取索引对应段落 | 需用户确认（例证①：定位类问题如「XX在第几章」完成第 1 级定位后直接进第 2 级，见第二节；例证②：文风蒸馏材料收集的索引小节读取由蒸馏触发词整体授权，见第九节文风蒸馏） |
| 读取全部索引内容 | 需用户明确说出 |
| 读取原文对应段落 | 需用户明确说出，且按行号范围读取（例证：文风蒸馏材料收集的 ≤500 行/次抽查由蒸馏触发词整体授权，见第九节） |
| 全文查看 | 需用户显式授权 |

**授权状态加载与作用域**：本节开头的授权前置是唯一加载入口。
授权记录必须符合 `索引库/_授权状态.yaml.example` 的字段：`operation`、`novel`、`author`、
`scope`、`grant_type`、`granted_at`、`expires_at`、`status`。`read_metadata` 默认允许；
一次性授权只存在当前对话，不写成长期授权。持久文件只保存用户明确同意长期有效的授权，
且只对记录的小说、操作和范围生效；不能用“读某书原文”授权扩大到其他书、全文或创作外的新任务。

**豁免条款**：授权文件中已记录且作用域匹配的长期授权无需当次确认；未记录、已过期、
范围不匹配或无法解析的一律按上表当次确认。定位类/蒸馏触发词的豁免只覆盖完成该目的
所需的索引/抽样读取，不覆盖全文查看、扩大抽样或无关文件。
**撤销授权**：用户可随时要求撤销；将对应记录标为 `revoked` 或删除后，立即恢复按上表
确认。每次交付可注明本次实际读取范围和授权依据，防止执行者偷扩范围。

### 6.1 诱导性全文请求识别

以下话术视为变相全文查看，应拒绝并引导走分级流程：

| 用户话术 | 判定 | 回应 |
|----------|------|------|
| "把整本书给我看看" | 全文请求 | "请先通过索引定位到具体章节，我再帮您查看原文" |
| "总结一下这本小说" | 概况请求（v4 起不再判为全文请求） | "我可以先给出索引概况（元数据 + 小说索引的概况/亮点速查），需要原文请指定章节" |
| "把第1章到最后一章都列出来" | 变相全文请求 | "这涉及大量原文，请指定具体章节范围" |
| "列出所有章节内容" | 变相全文请求 | "我可以列出所有章节标题（元数据），需要哪章的详细内容？" |

### 6.2 连续追问防护

用户连续追问原文超过 3 次时，主动提醒：
"您已连续查看多段原文。如果需要大量原文，是否授权全文查看？
（授权后将直接读取源文件，可能消耗较多 tokens）"

### 6.3 索引未命中处理

当查询内容在索引中找不到时：

1. 告知用户："索引中未收录该内容"
2. 建议扩大搜索范围（尝试其他章节索引）
3. 如用户坚持，询问是否需要**增量索引**或**全文搜索**（需授权）

**全文搜索的操作定义（v4.5 拷问定稿，可检查）**：
全文搜索 = **关键词定位，不是全文阅读**。
- 操作：对目标段文件执行关键词检索（Grep/Select-String），**只返回命中行号列表**
  （每段 ≤20 处），**不读取命中内容**
- 交付格式（必须按此输出，防执行层偷懒把搜索变读全文）：
  ```
  **全文搜索**：<关键词> 命中 <N> 处
  - <段文件名>：行 <a>、行 <b>、行 <c> …
  查看具体命中内容请指定行号（按第 4 级读取，≤500 行/次，需明确说出）
  ```
- 授权边界：授权覆盖"执行搜索 + 返回行号"；**不自动延伸为阅读授权**——
  用户要求查看命中内容时，回到第 4 级按行号范围读取、逐次确认

## 七、多本小说检索

当 `索引库/章节索引/` 下有多本小说的索引（平铺混放）时：

1. 第 1 级先通过 `小说索引/` 展示所有小说的元数据概览
2. 用户未指定小说 → 询问"您要查哪本小说？"
3. 用户指定小说 → **按 `<小说名>-<作者>-` 前缀过滤**章节索引文件，
   只读该小说的索引（防止跨书混入）
4. 同名小说通过"作者"字段区分

### 跨书联动检索（v4.5 审查新增，可选）

**触发条件**：用户跨书比较，如「哪本书里写过类似桥段」「这几本书的爽点风格
有什么差异」。

**操作**（只读索引，第 1-2 级范围，不读原文）：
1. 第 1 级列出全部小说索引 frontmatter（书名/作者/包含元素）
2. 按查询意图，跨书 grep 各书的**章节索引**（关键词或标签定位，见第三节
   语义召回）
3. 按书汇总交付：
   ```
   跨书检索「退婚名场面」：
   - 《斗破苍穹》（天蚕土豆）：第3章 退婚+三年之约
   - 《完美世界》（辰东）：第1卷 退婚+大婚之变
   ```
4. 边界：跨书检索只汇总索引摘要，不读任何一本的原文；用户要原文 → 回到
   单书第 4 级按行号读取

## 八、检索回答格式规范

所有检索结果统一格式。**无章节小说（分段方式：按字数切分）**不套用「第X章」表述，
命中结果写「第X万字~第Y万字 段」：

```
**命中结果**：<小说名> 第X章「章节名」
**索引摘要**：<从索引表提取的梗概>
**原文位置**：<段文件相对路径> 第 X 行 ~ 第 Y 行（段文件内行号）
**索引文件**：<索引文件名>
**是否读取原文**：<询问用户>
```

## 九、阶段三：基于索引创作（可选）

创作前置门禁：确认目标小说已在索引库、加载授权状态、明确素材读取范围；未建索引或索引损坏时走降级路径，不得凭空声称使用了索引素材。交付必须列出素材出处、防撞车结果和实际读取范围。

### 触发条件
用户明确说「根据索引写」「基于XX桥段创作」「防撞车」「续写」「仿写」

**触发分流（v4.2 明确）**：「续写」「仿写」若用户**指定了作者/作品**（如「仿XX的
风格续写」「按《YY》的笔法写」）→ 走本阶段「文风蒸馏」小节（轻量蒸馏默认）；
若**未指定作者**、仅指桥段/套路复用 → 走本小节基础流程（检索素材 + 防撞车）。
无法判断时先按基础流程走，产出时询问是否需要带文风。

### 流程

1. **先走检索流程**（按四级层级收集素材）
2. **防撞车清单**：列出原剧情已用过的套路（破案手法、反转类型、名场面），
   新剧情全部避开

### 文风蒸馏（可选，v4.2 新增，引用式集成）

**触发条件**：用户明确要求按某位作者/某部作品的笔法创作，如「用XX的笔法写」
「仿XX文风续写」「按《YY》的风格写」。

**输入前提检查（v4.5 拷问定稿）**——目标作品必须可溯源，不得凭空捏造文风：
1. **目标作品已在索引库**（有章节索引）→ 正常走轻量蒸馏
2. **未建索引但有原文文件** → 明确告知「该书未建索引，无法轻量蒸馏」，给出
   降级路径：①先建索引（**推荐**——顺带获得全书检索能力，之后蒸馏免费）
   ②直接提供文件给 wenfeng-skill 完整蒸馏 ③仅按基础创作流程仿桥段（不仿文风）
3. **无原文文件** → 只走基础创作流程，不虚构文风（与 wenfeng「信息不足先说明
   缺口，不编造」原则一致）

**作者级触发（v4.5 拷问定稿）**：「用XX的笔法写」中的 XX 是**作者**且库中
有多本书时：先列出该作者在库中的书让用户**选一本**蒸馏（一句话成本，换来
风格明确）；用户表示"都行/综合"时，取金句/爽点最密集的一本（第 1 级元数据
「包含元素」粗筛，零额外读取），风格卡诚实边界标注「基于《XX》，非该作者
全部作品」。**禁止多本混合蒸馏**——平均风格哪本都不像（wenfeng 单本原则）。

**两级路径**：
- **轻量蒸馏（默认）**：直接基于索引库材料提炼风格卡，不读全文（本小节流程）
- **完整蒸馏（重载）**：调用外部 `wenfeng-skill`（单本小说版，独立技能）对段文件/
  源文件做全流程蒸馏，产出可安装的写作 SKILL.md——发布级、批量使用场景才需要。
  两个技能文件保持独立，互不拷贝内容。

**轻量蒸馏流程**：

1. **收集蒸馏材料**（按四级路径走，不扩大范围）：
   - 锚点原句 ← 各段章节索引「金句/名场面」小节（逐字摘录、带段文件行号）
   - 叙事模型 ← 「创作手法分析」小节（叙事技巧/节奏控制/人物塑造）
   - 情节技法 ← 「爽点/看点」「本段总结·情绪弧线」小节
   - 语言指纹 ← 原文段文件抽查（第 4 级，≤500 行/次）；v4.6.6 起由脚本在
     预算内自动实测（见第 3 条脚本分工），编排器复核后采用
   **抽样上限（v4.6）**：段数 ≤10 → 全部收集；段数 >10 →
   **抽样 8~10 段**，且原文语言抽查总量不超过被抽段总行数的 5%，单次 ≤500 行；
   优先：①金句/名场面最密集的段（按第 1 级元数据
   「包含元素」含金句/名台词标签粗筛，零额外读取）②首段与末段
   ③爽点密集段。每次抽查记录累计段数/行数，达到上限停止。风格卡「诚实边界」必须标注
   「基于抽样 N/共 M 段、原文抽查累计 X 行」，不得装成全书结论。
   **授权边界**：用户主动要求「用XX的笔法写」可授权本次轻量蒸馏所需的索引小节和预算内原文抽查；
不授权全文查看、额外抽样、其他作品或后续独立任务。实际抽查累计段数/行数必须写入风格卡诚实边界。
2. **风格卡 v2（九节，v4.6.6）**：按 ①一句话定性（宏观 medium 式，≤40 字）
   ②量化语言指纹（键值对指标）③叙事模型 ④母题意象 ⑤人物塑造 ⑥情节技法
   ⑦组合公式 ⑧不可写（Never 句式禁则）⑨诚实边界 产出；③~⑥每维写
   「观察 + 可执行规则」。②的指标写成可检查的阈值（如「对话占比 0.3~0.5」），
   来源为脚本实测（素材底稿「量化语言指纹」节）或编排器按第 4 级抽查原文
   人工统计；金句锚点挂在②，每轴 ≤2 句、每句 ≤15 字、标注来源。
   **锚点（v4.5 拷问定稿）**：允许极少量短锚点——每轴 ≤2 句、每句 ≤15 字的
   金句原文摘录，并标注来源（作品 + 段文件行号）。短锚点是蒸馏可信度的核心
   （规则会骗人，原句不会），属分析性引用；段落级复述/情节复述仍禁止（见第 5 条）。
   **产出形态与存放（v4.5 拷问定稿）**：默认在对话中直接呈现（与防撞车清单同列，
   供本次创作使用），**不落盘**；用户明确要求存档时，写入
   `<INDEX_LIB_DIR>/../风格卡/<小说名>-<作者>/style-card.md`（索引库**同级目录**，
   不进索引库三目录——保持索引库结构纯净，风格卡属用户数据，随索引库删除/重建
   不受影响），每次蒸馏**覆盖**同名文件，天然保持最新版。落盘时同目录再写一份
   创作侧机读的 `style-card.json`（契约见 `schemas/style-card.schema.json`）。
   完整蒸馏产物（可安装的写作 SKILL.md）由 wenfeng-skill 输出到技能库；
   风格卡与写作 SKILL.md 互为溯源引用（风格卡标注「完整版见 `<name>-novelist`」，
   wenfeng-skill 产出时标注「轻量版见 style-card.md」）。
   **存档风格卡 frontmatter 元信息**（追更后一眼可知时效，过期即可免费重蒸馏）：
   ```
   ---
   作品: 《XX》
   蒸馏日期: YYYY-MM-DD
   基于索引范围: 第1章~第500章（追更前）
   抽样: 8/100 段
   蒸馏方式: 轻量蒸馏
   完整版: <name>-novelist（如已生成）
   ---
   ```
3. **技法过滤三准则**：复现性（索引中出现多次）/ 生成力（能指导新场景）/
   排他性（非通用建议）——三选二才写入；不满足的降级为偏好或不写
   **脚本分工（v4.6.5，v4.6.6 扩充）**：`scripts/style_distillation.py` 产出的是「素材底稿」——
   从索引小节机械抽取的原料（含未截断前的剧情概要），**不是风格定性，不得作为
   最终交付**。最终风格卡 v2 必须由编排器（AI）基于底稿重写：每维「观察 +
   可执行规则」、应用技法过滤三准则、锚点每轴 ≤2 句且每句 ≤15 字并标注来源；
   底稿中的长金句与情节概要不得原样带入最终卡（版权纪律）。
   底稿另含脚本实测的「量化语言指纹」（原文抽样预算
   min(500, 被抽段总行数×5%)）与「组合公式」模板（v4.6.6）：指标复核后
   直接采用，组合公式由编排器填充后随创作稿输出。
4. **结合创作**：风格卡 + 防撞车清单 + 索引素材三者结合产出，并附「创作思路拆解」
5. **版权纪律**：风格卡以抽象规则为主；**唯一豁免**为②量化语言指纹节的短锚点
   （每轴 ≤2 句、每句 ≤15 字、标注来源），禁止段落级复述、情节复述、
   近似改写与长文摘抄；蒸馏产出不进索引库（金句小节的逐字摘录是供检索
   定位的，不是蒸馏的复述依据）
6. **交付确认（升级选项）**：轻量蒸馏最终输出（风格卡 + 创作稿）交付时，
   必须附一句询问：「是否需要升级为完整蒸馏（调用 wenfeng-skill 生成可安装的
   写作 SKILL.md）？」——用户确认后才调用完整蒸馏；未确认时本次轻量蒸馏即为
   最终交付，不得擅自升级（升级会额外消耗完整蒸馏的 tokens 与流程）

### 扩展接口（ADR-0009）

完整文风蒸馏通过 `INDEX_STYLE_SKILL` 环境变量或 `orchestrate.py style --style-skill` 指定外部 skill：

- 指向 `.py` 脚本：编排器用 `subprocess` 调用并传入 `--lib/--novel/--author`。
- 指向目录：视为外部 skill 根目录，按 **`SKILL.md` 的 `style-entry: 相对路径` →
  `scripts/run_style.py` → `run.py`** 顺序解析入口（命中即停；`style-entry` 声明了却
  指向不存在的文件时直接报错，不悄悄回落到别的入口）。解析到的入口同样以
  `subprocess` 调用，参数为 `--lib <索引库> --novel <书名> --author <作者>
  --output-dir <风格卡目录>`（未指定 `--output-dir` 时为索引库同级
  `风格卡/<书名-作者>`），外部技能须把风格卡写进该目录；随后编排器在该目录寻找
  产物 `style-card.md`（其次取 stdout 打印的真实路径）。
- 指向命令字符串：用 `shlex.split` 拆分后执行，等待并检查返回码。

解析不到入口时返回人话报错（点名查过的候选与修法）；外部技能非零退出时返回
`{"mode": "external", "error": ...}`，`error` 取其 stderr **尾部摘要**——已剔除 Python
堆栈帧、并把 `api_key`/`token`/`password` 之类的值替换为 `<已隐去>`，不外泄密钥与 traceback。
两种方式成功后结果都带 `path`（卡片文件）与 `json_path`（见下）。

**结构化风格卡（C7-2）**：`style-card.md` 旁同时写 `style-card.json`（同目录同词干），
字段为 v2 九节的机器可读版（作品/作者/蒸馏日期/基于索引范围/抽样/完整性/来源/
量化语言指纹/叙事模型/金句锚点/母题意象/人物塑造/情节技法/组合公式/不可写/诚实边界），
`完整性` 取 `轻量|完整`、`来源` 记索引库与实际调用的外部技能入口。契约文件为
`schemas/style-card.schema.json`，写盘前由 `scripts/style_card_schema.py`（零依赖本地校验器，
读取 schema 文件而非硬编码规则）自校验；不合格只告警不中断（md 仍是人读权威）。
外部技能若自带 `style-card.json` 则沿用不覆盖；否则由本技能从其 `style-card.md` 反解补齐。
结合创作时优先读 json，避免从 Markdown 里抠字段。

未配置 `INDEX_STYLE_SKILL` 且未传 `--style-skill` 时，默认走轻量蒸馏，从小说索引与章节索引生成轻量风格卡；当前不内建完整蒸馏降级方案。外部 skill 失败时返回 `{"mode": "external", "error": ...}`，不继续生成轻量风格卡。
