# 建立索引：执行协议 v4.8.1

> **何时读取**：进入“建库”“追更/重建”“验证”“备份/恢复/删除”分支时读取本文件的对应小节；不要为普通检索加载本文件。
>
> **执行原则**：脚本是实际执行入口，本文件是编排器的决策、门禁和恢复协议。每一步都要产生可核对证据；没有证据就停在 `BLOCKED` 或 `NEEDS_REVIEW`。

## 0. 共享约定

- `<技能目录>` = 本技能 `SKILL.md` 所在目录；`<索引库>` = `<技能目录>/.env` 的 `INDEX_LIB_DIR`，为空则 `<技能目录>/索引库`。
- 索引 frontmatter 的 `源文件` 是相对 `<索引库>` 的路径；禁止按 cwd 解析，禁止允许 `..` 越出索引库。
- 标准目录固定为：`小说原文/`、`章节索引/`、`小说索引/`。`build_segment_index.py --out` 仅为兼容参数，不属于标准闭环，不得用于正式交付。
- 运行清单至少记录：任务状态、书名/作者、源文件路径和 hash、索引库路径、执行器、段数、索引数、失败/待人工段、验证结果和恢复命令；不得记录 API key。

## 1. 建库：ROUTE → PREFLIGHT → PLAN → SPLIT → GENERATE → VERIFY → PUBLISH

### 1.1 ROUTE / INTAKE：确认任务

收集并复述：

1. 源文件**绝对路径**（只接受 `.txt` / `.md`）；
2. 小说名和作者；
3. 是否多卷、是否已有索引、是否为追更；
4. `<索引库>` 位置和是否允许写入。

用户没有确认书名、作者、源文件或写入范围时，停止，不运行脚本。

### 1.2 PREFLIGHT：环境和数据预检

逐项记录 `PASS` / `BLOCKED`：

- 源文件存在、可读、编码可由脚本读取；
- `.env` 存在则读取 `INDEX_EXECUTOR` 和 `INDEX_LIB_DIR`，不存在则采用 `direct` + 默认库并提示 API 配置；
- direct 模式的 API URL、模型、key 均已配置（只报告是否配置）；
- subagent 模式的宿主确实有 Agent/子代理能力；否则回退 direct 或停在 `BLOCKED`；
- 索引库不是另一部书的库，三目录可创建；
- 已有同名书时比较源文件 hash，明确是“续更”“重建”还是“拒绝覆盖”；
- 执行前有备份或用户明确接受重建成本。

**通过条件**：所有检查有证据；任一 BLOCKED 都不得进入 SPLIT。

### 1.3 PLAN：结构摸底和分段确认

使用 `scripts/chapter_patterns.py` 的同源规则检查：中文章/回/话/集、卷级标题、序章/番外、英文标题、纯数字标题和无章节文本。

分段默认值：

- 有章节：每 5 章一段，首尾段可不足 5 章；
- 无章节：目标约 1 万字符一段，按段落边界切分，末段允许为剩余短段；
- 多卷且卷内章号重复：每个卷文件必须传 `--volume 第X卷`；
- 日期、自定义分隔符：脚本不会自动识别，必须由编排器人工映射，或明确降级为按字数切分；
- 正文疑似误判为章节、首章前有前导语、标题重复或缺失：标记 `NEEDS_REVIEW`，向用户说明取舍。

向用户展示：标题数、分段数、分段规则、预计 API 调用量/时间和已知风险，等待确认。

**通过条件**：用户确认方案；没有把“模型自行判断”当作非标准格式的验证。

### 1.4 SPLIT：生成段文件

标准命令（脚本路径和库路径都使用绝对路径）：

```text
uv run --with requests --with python-dotenv python "<技能目录>/scripts/split_segments.py" "<源文件>" --novel "小说名" --author "作者" --lib "<索引库>"
```

多卷：追加 `--volume "第X卷"`；追更：追加 `--append`；覆盖已有段：只有用户确认后追加 `--force`。

脚本门禁：编码/BOM 回退、frontmatter、段非空、章节边界连续、字符守恒、同名内容冲突和段号唯一。

**通过条件**：

- 每个段文件存在且非空；
- 段编号唯一且按书可排序；
- 段 frontmatter 的小说名、作者、章节范围、对应索引、分段方式完整；
- 首章前未纳入段的内容已经解释；
- 无冲突、无不安全锚点。

### 1.5 GENERATE：生成章节索引

#### direct（默认）

```text
uv run --with requests --with python-dotenv python "<技能目录>/scripts/build_segment_index.py" "<索引库>/小说原文/<小说名>-<作者>/" --lib "<索引库>" --workers 32
```

追更可加 `--skip-existing`；只有明确知道代价时才使用 `--no-fix` / `--no-range`。脚本会在 `done` 前检查空响应、截断、frontmatter、源文件回指、段编号、总章节数和章节小节数量。

#### subagent（兼容路径）

仅在宿主提供 Agent/子代理能力时使用 `templates/子代理任务模板.md`。每项任务必须包含：段文件绝对路径、索引库绝对路径、输出绝对路径、章节列表、模板绝对路径和失败回传格式。子代理只能读取指定段文件和技能模板，不得读取其他书或修改段文件。能力不可用时回退 direct，不得伪造派发结果。

**通过条件**：每个段恰有一个结构合法的章节索引；失败段进入 `NEEDS_REVIEW`，不计入已完成数量。

### 1.6 VERIFY：结构、行号和内容门禁

按顺序执行：

```text
uv run --with requests --with python-dotenv python "<技能目录>/scripts/_验证批次.py" --lib "<索引库>"
uv run --with requests --with python-dotenv python "<技能目录>/scripts/verify_and_fix_lines.py" "<索引库>/章节索引" --lib "<索引库>"
uv run --with requests --with python-dotenv python "<技能目录>/scripts/check_line_refs.py" --lib "<索引库>" --detail
```

检查含义：

| 层级 | 必查内容 | 通过条件 |
|---|---|---|
| 结构 | 三目录、段/索引数量、按书编号、frontmatter、源文件回指、章节标题 | 工具返回 0 |
| 校准 | 金句、区间、引用一致性、概要区间 | 无未处理硬错误 |
| 体检 | 行号两端、倒序、越界、章外、缺源/损坏文件 | 工具返回 0 |
| 质量 | 首段 + 金句/爽点密集段；概要忠实、章节覆盖、标签变体、行号抽查 | 概要虚构 0；覆盖 100%；行号偏差 ≤2；漏组 ≤2 |

追更必须重新执行全部 VERIFY；不能只刷新小说导航。任何失败、待核行号、损坏索引、占位符或待人工段都阻止 PUBLISH。

### 1.7 PUBLISH：合并导航和交付

只有 VERIFY 通过后运行：

```text
uv run --with requests --with python-dotenv python "<技能目录>/scripts/build_novel_index.py" --novel "小说名-作者" --lib "<索引库>" --force
```

编排器补写并检查：全书概况、亮点速查、伏笔全局追踪表、人物关系链；确认 `--force` 没有覆盖已有补写。交付前形成报告：

```text
状态：DONE / BLOCKED / NEEDS_REVIEW
范围：书名、作者、章节/段范围
读取/生成：实际路径和源文件 hash
验证：三条命令返回码、统计、质量抽检
失败项：无 / 具体列表
恢复/下一步：可直接执行的命令或人工决定
```

## 2. 追更和重建

### 2.1 追更顺序

1. 记录旧源文件 hash 和新源文件 hash；
2. 运行 `split_segments.py --append`（多卷逐卷、串行）；
3. 只重跑新增段或 hash 变化的末段；
4. 完整执行 VERIFY；
5. VERIFY 通过后才刷新小说导航。

同名章/番外正文锚点出现多个完全相同候选、源文件不是旧段的延续、段号无法唯一接续时停止并要求 `--force` 全量重切或人工映射。

### 2.2 强制重建

删除目标 `-idx.md` 或清理对应 SQLite 任务记录，再运行单段命令。修改过段文件会改变 hash，旧索引必须重跑；不直接编辑段文件来“修行号”。

## 3. 验证、备份、恢复和删除

### 3.1 单独验证

用户说“体检/验证索引库”时直接进入 VERIFY，交付工具返回码和问题清单；不能只说“检查过”。

### 3.2 备份/恢复

备份至少包括 `<索引库>/小说原文`、`章节索引`、`小说索引`、`.index_state.db`；风格卡位于索引库同级，需另行备份。恢复后重新运行完整 VERIFY，不能把复制成功当成可用。

### 3.3 删除/重置

删除是不可逆操作。先列出书名、作者、源段目录、章节索引、小说索引、风格卡和对应断点记录，取得二次确认后逐项删除；随后检查无孤儿文件和无残留任务记录。整体重置同样需要二次确认。

## 4. 失败恢复表

| 失败 | 状态 | 恢复 |
|---|---|---|
| API 未配置/宿主无子代理 | BLOCKED | 配置 direct 或切换可用宿主 |
| 源文件不存在/格式不支持 | BLOCKED | 提供正确文件或先转换 |
| 章节格式非标准 | NEEDS_REVIEW | 人工映射或按字数降级 |
| 段文件冲突/锚点不唯一 | NEEDS_REVIEW | 确认覆盖、`--force` 或人工拆分 |
| LLM 截断/空响应/结构不符 | NEEDS_REVIEW | 重跑该段；累计失败交人工 |
| 行号待核/体检失败 | NEEDS_REVIEW | 人工复核或重跑，不发布 DONE |
| 追更后验证失败 | NEEDS_REVIEW | 修复受影响段，重新 VERIFY |

## 5. 命令索引

- 统计/查看：优先使用文件工具；Git Bash 可用 `wc -l`，PowerShell 可用 `Measure-Object`，不要假设 shell。
- 结构验证：`uv run --with requests --with python-dotenv python "<技能目录>/scripts/_验证批次.py" --lib "<索引库>"`
- 直调生成：`uv run --with requests --with python-dotenv python "<技能目录>/scripts/build_segment_index.py" ... --lib "<索引库>"`
- 行号校准：`uv run --with requests --with python-dotenv python "<技能目录>/scripts/verify_and_fix_lines.py" "<索引库>/章节索引" --lib "<索引库>"`
- 行号体检：`uv run --with requests --with python-dotenv python "<技能目录>/scripts/check_line_refs.py" --lib "<索引库>" --detail`
