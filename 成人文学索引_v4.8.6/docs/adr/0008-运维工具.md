# ADR-0008: 增加删除、重命名、迁移三本运维脚本

## 背景

小说索引 v4.6 提供了建库、追更、重跑、验证等完整写入流程，但缺少日常运维操作：删除一本书、重命名书/作者、迁移索引库根目录。用户目前只能手动删文件、改 frontmatter，容易遗漏 SQLite 断点记录或 `源文件` 路径引用，导致后续验证失败。

## 决策

新增三个运维脚本，优先级依次交付：

1. `scripts/delete_novel.py`：删除指定书籍的段文件、章节索引、小说索引，并清理 SQLite 断点记录。
2. `scripts/rename_novel.py`：批量重命名书籍相关文件/目录，并同步更新 frontmatter 中的 `小说名称`、`作者`、`源文件`。
3. `scripts/migrate_library.py`：整体迁移索引库根目录，递归更新 `源文件` 路径前缀，可选保留或重建 SQLite 断点库。

## 理由

1. **删除是最常见操作**：用户试建索引失败、或想清理旧书时，需要安全删除所有相关产物。
2. **重命名影响一致性**：小说名或作者名一旦写错或变更，必须同步更新文件系统与索引元数据，否则 `源文件` 回指会失效。
3. **迁移是环境变化刚需**：换电脑、换云盘路径、分享索引库时都需要迁移工具保证路径一致性。

## 备选方案

- **让用户手动操作**：被否，因为容易遗漏断点库和 frontmatter，导致隐性错误。
- **在编排器里内置这些命令，不单独出脚本**：被否，因为高级用户可能只想执行单一运维操作，不必进入完整编排流程。

## 后果

- 需要在删除、重命名前做二次确认（`--yes` 强制跳过），防止误删。
- `rename_novel.py` 需要识别并更新所有引用旧书名/作者名的字段，逻辑较复杂，需要充分测试。
- `migrate_library.py` 需要处理相对路径与绝对路径两种情况，并保留用户选择是否重建断点库。
