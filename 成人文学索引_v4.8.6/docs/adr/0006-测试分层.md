# ADR-0006: 新增 pytest 单元测试层，保留现有集成测试

## 背景

`scripts/_功能测试.py` 覆盖了 28 个功能回归点，全部通过，主要验证正常流程和已踩坑回归点。但随着编排器、向量检索、更多外部依赖的加入，LLM 输出非法、网络超时、SQLite 锁等待、磁盘不可写等故障路径需要被系统性地测试。把所有这些异常场景都塞进集成测试会导致测试变慢且难以稳定复现。

## 决策

1. 新建 `tests/` 目录，使用 pytest + `unittest.mock` / `responses` 编写单元测试和故障路径测试。
2. `scripts/_功能测试.py` 继续作为集成测试，验证端到端真实流程。
3. 提供统一的测试入口（如 `scripts/run_tests.sh`），先跑单元测试，再跑集成测试。
4. 故障路径测试优先覆盖：LLM 返回非法 frontmatter、SSE 流中断、API 429/503 退避、SQLite 并发写入、目标目录只读/满盘、YAML 解析异常。

## 理由

1. **速度快**：单元测试不依赖真实 LLM 调用和临时目录，反馈周期短。
2. **稳定性高**：mock 外部依赖后，故障场景可稳定复现。
3. **不破坏现有测试**：保留 `_功能测试.py` 作为“全链路验收”。

## 备选方案

- **继续扩展 `_功能测试.py`**：被否，因为集成测试难以模拟所有外部故障，且会越来越慢。
- **直接替换 `_功能测试.py` 为 pytest**：被否，因为现有集成测试已经成熟有效，重写成本高且风险大。

## 后果

- 需要新增 `pytest`、`responses` 等开发依赖。
- 底层脚本需要把核心逻辑拆成更纯粹的函数，方便 mock 和测试（这是好的副作用）。
- 需要定义测试数据工厂（fixtures）生成标准 frontmatter、段文件、mock API 响应等。
