# ADR-0004: 引入可选的语义/向量检索模块

## 背景

小说索引 v4.6 的检索体系以关键词召回为核心：frontmatter 标签、`包含元素标签词汇表.md` 和 Grep 文本匹配。这种方式对“按标签查桥段”“按书名查原文”非常有效，但面对自然语言描述的情绪、节奏、写法（如“找主角被当众羞辱后隐忍反击的段落”）时，召回率受限于用户是否使用了索引中的标签词。

## 决策

增加可选的向量检索模块：

- `scripts/semantic_index.py`：基于章节索引文本块生成 embedding，存储到本地向量索引。
- `scripts/semantic_search.py`：提供语义召回接口，返回候选段并附相似度分数。
- 默认关闭；用户通过环境变量或命令行显式开启后才进入向量路径。
- 检索时采用 hybrid search：关键词召回作为默认主路径，语义召回作为可选增强；结果融合后返回。

## 理由

1. **补齐高阶查询场景**：自然语言式创作辅助查询需要语义匹配，仅靠标签无法覆盖。
2. **保持默认简单性**：默认不启用，现有工作流、授权体系和成本模型不受影响。
3. **向后兼容**：未启用向量索引时，系统完全退化为现有关键词检索；已建的关键词索引文件无需重建。

## 备选方案

- **只扩大标签词汇表**：被否，因为标签体系再全也无法覆盖用户的自然语言表述，维护成本也会指数上升。
- **强制所有安装都带 embedding 依赖**：被否，因为会增加包体积和硬件要求，与“轻量 skill”目标冲突。
- **完全替换关键词检索为向量检索**：被否，因为关键词检索对精确标签查询更可控、成本更低、可解释性更好。

## 后果

- 新增可选依赖（如 sentence-transformers 或 OpenAI embedding API）。
- 需要定义向量索引的存储格式和更新策略（增量更新、与 Markdown 索引版本对齐）。
- 需要更新 `references/索引内容.md` 和 SKILL.md，说明四级读取在启用向量索引后的扩展规则。
- 检索授权需要细化：生成 embedding 是否属于“读取完整索引”或更高级别？需要在授权粒度表中补充说明。
