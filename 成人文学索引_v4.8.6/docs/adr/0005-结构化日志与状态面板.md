# ADR-0005: 用 Python logging 替换 print，并增加状态查询命令

## 背景

小说索引 v4.6 的脚本目前主要使用 `print` 输出进度和状态。随着编排器、向量索引、多书并行等能力引入，标准输出将变得难以解析，用户和宿主 Agent 也无法快速获取“当前有多少书在建、哪些段失败、累计 token 多少”等全局信息。

## 决策

1. 所有脚本统一使用 Python 标准库 `logging` 输出日志；保留人类可读格式作为默认，同时支持 `JSON` 格式输出（通过 `--log-format json` 或环境变量 `INDEX_LOG_FORMAT=json` 开启）。
2. 在编排器中新增 `status` 子命令，读取 SQLite 断点库，输出当前索引库的全局状态摘要，包括每本书的处理进度、失败段列表、token 累计消耗、最近更新时间。
3. `print` 仅在 CLI 明确需要向终端展示最终用户可见的简短结果时保留（例如 `orchestrate.py status` 的表格输出），其他内部进度信息全部走日志。

## 理由

1. **机器可解析**：JSON 日志让宿主 Agent 可以监听失败、token 消耗等事件，做自动化重试或告警。
2. **人可读**：默认文本格式不影响现有用户观感。
3. **统一状态视图**：`status` 命令利用已有的 SQLite 断点库，无需新增存储组件。

## 备选方案

- **继续用 print，但增加一个解析器把 print 输出转成结构化数据**：被否，因为解析 print 输出脆弱且容易因文案改动失效。
- **引入外部可观测性系统（如 Prometheus/OTel）**：被否，因为 skill 应保持无外部依赖，避免增加部署复杂度。

## 后果

- 所有脚本需要逐步替换 `print` 为 `logging.info/debug/warning/error`。
- 需要定义日志字段规范（至少包含 `novel`, `author`, `segment`, `operation`, `status` 等上下文字段）。
- `status` 命令的界面格式需要在 README_CN.md 中说明示例。
