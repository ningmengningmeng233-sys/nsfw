# ADR-0003: 用集中式编排器实现 SKILL.md 状态机

## 背景

SKILL.md 定义了完整的状态机（ROUTE → PREFLIGHT → PLAN → EXECUTE → VERIFY → PUBLISH）和 6 条分支路由，但当前技能只提供了完成单步任务的底层脚本（split_segments.py、build_segment_index.py 等）。实际运行时，宿主 Agent 或用户必须手动判断当前处于哪个状态、下一步调用哪个脚本、失败时如何回退，状态机停留在文档层面。

## 决策

引入一个集中式编排器脚本 `scripts/orchestrate.py`，暴露 `init`、`build`、`verify`、`resume`、`delete` 等子命令。编排器内部维护状态流转，底层脚本继续保留独立调用能力。

## 理由

1. **降低宿主 Agent 负担**：Agent 只需识别用户意图并调用一个入口，不必在每次交互中重新理解状态机。
2. **保证流程一致性**：状态判断、断点恢复、前置校验由代码统一实现，减少因模型遗忘协议导致的流程错误。
3. **保留灵活性**：底层脚本仍可单独调用，满足高级用户和现有 CI 工作流的需求，不破坏已有使用方式。

## 备选方案

- **让宿主 Agent 自己按 SKILL.md 协议调度**：保持现状，不新增编排器。被否，因为状态机复杂且需要记忆上下文，宿主模型容易出错。
- **把所有脚本合并成一个巨型脚本**：被否，因为会丧失单步调试和独立复用的能力，与现有 `--append`、`--force` 等细粒度控制冲突。

## 后果

- 新增一个需要长期维护的入口文件。
- 底层脚本需要暴露更稳定的命令行接口和返回码，供编排器判断状态。
- 需要更新 SKILL.md 和 README_CN.md，把“编排器”作为推荐入口。
