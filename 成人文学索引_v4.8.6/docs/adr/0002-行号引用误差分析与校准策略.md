# 索引行号引用误差的根因分析与校准策略（v3.9）

## 背景：发现了什么问题

章节索引中的行号引用（如「蓝银草二次觉醒为蓝银皇（行69-71）」）与实际原文位置不符——真实位置在段文件**行 669-671**，索引写成了 69-71（丢了一位数字）。

## 一、现象与影响面（全库体检，3536 个索引、145,310 处行号引用）

| 指标 | 数量 | 占比 |
|---|---|---|
| 严格越界（行号 > 段文件总行数，**必然错误**） | 15 处 | 0.01% |
| 章外引用（不在所属章范围，**疑似错误**） | 9,215 处 | 6.34% |
| —— 其中轻微偏差（≤10 行） | 2,714 处 | 1.9% |
| —— 中等偏差（11~50 行） | 1,404 处 | 1.0% |
| —— 大偏差（>50 行，跨段串用/丢位） | 5,097 处 | 3.5% |
| 涉及的索引文件 | 1,163 / 3536 | 33% |

结论：**不是每个索引都有问题**（67% 的文件行号引用完全干净），但大偏差引用（3.5%）会把检索者带到错误的章节区域，属于必须治理的质量问题。

## 二、根本原因（LLM 机制层）

**行号引用是「注意力定位」而不是「计算」**。直调引擎把带行号的段文件全文（约 1.5~2.5 万字符，每行前缀 `NNNNN:`）一次性喂给 LLM，要求它在生成索引时引用「精确行号」。问题出在：

1. **注意力在长上下文中对离散数字的忠实度有限**：行号是离散符号，上下文越长，模型「复制」具体数字时越容易出现偏差——它不是像程序那样计算行号，而是凭注意力「回忆」某个事件大致在第几行附近，再补一个数字。
2. **错误模式高度规律**（与上述体检数据对应）：
   - **位数丢失**：669 → 69（最常见，本次案例）
   - **跨段串用**：258 行的段文件引用行 679——模型把其他段/其他位置的行号抄了过来
   - **frontmatter 混入**：段文件行 1~8 是 YAML 元数据，模型偶尔把元数据行也算进行号（引用「行1~5」）
   - **近似偏移**：章边界附近差 1~10 行
3. **转述与原文的措辞差异**（影响后续校准的关键）：索引里的行号引用分两类——
   - **金句引用**：模板强制「逐字摘录原文」（`"原文"（行NNN，简述）`），原文与索引一致，可被文本指纹回查修正；
   - **区间/短语引用**（爽点/伏笔/概况里）：是 LLM 对剧情的**转述**（如「蓝银草二次觉醒为蓝银皇」），措辞与原文不同（原文是「蓝银草二次觉醒。露出了真面目」），无法用文本回查——这是校准命中率低的根本原因。

## 三、为什么没被兜底（技能架构层）

1. 直调引擎生成索引后，会运行自动校准脚本（`verify_and_fix_lines.py`），但**只覆盖金句格式**（`"原文"（行NNN，简述）`）——因为只有金句有原文可回查。
2. **区间/短语引用只有 check-only 检测**（报告不修改）：原设计假设行号偏差主要出现在金句（实测金句错位率约 1/3），对区间引用的校准是盲区。
3. 校准脚本本身有 bug：`--lib` 参数在 argparse 中声明但从未传入处理函数，多索引库场景下校准会找错库（本次已修复）。
4. 深层原因：**校准覆盖面与真实错误分布不匹配**——设计时只防御了已知错误类型（金句），未对区间引用做同样强度的兜底。

## 四、为什么不能彻底消除（本质约束）

1. **LLM 是概率模型**：任何「生成」行为都有固有误差率，行号是精度要求极高的数字引用，误差只能治理、无法归零。
2. **文本指纹回查有边界**：只有「逐字摘录」的引用能可靠回查（金句）；转述引用语言不同，无法回查。强制所有引用逐字摘录会显著增加 tokens 与索引体积，不现实。
3. **工程权衡**：完全消除需要「生成 → 后处理 → 人工复核」三级流水线，成本远超收益。行号在索引中的定位是「段内辅助锚点」，章节级定位由章标题行号承担（该层 100% 校准过）。

## 五、治理方案（v3.9 已实施）

三层治理，从源头到兜底：

| 层 | 措施 | 文件 |
|---|---|---|
| ① 生成端约束（治本） | 模板硬性要求新增第 8 条：**行号引用宁缺毋滥**——转述性描述不得附行号；需要精确行号时优先收进「金句/名场面」小节逐字摘录 | `templates/直调任务模板.md` |
| ② 校验端兜底 | 新增区间/短语引用校准 `fix_range_refs`：短语文本指纹回查段文件，**唯一命中且修正后不越界才改写**（区间保持原长度）；未命中/多命中一律保持原样（**绝不污染**），仅统计 | `scripts/verify_and_fix_lines.py` |
| ③ 工具修正 | 修复 `--lib` 参数不生效的 bug；新增 `--no-range` 开关 | 同上 |

校准设计原则：**只做高置信修正，不污染文件**——金句校准可回查所以直接修；区间引用只在唯一命中时修，其余保持原样并在统计中报告（`待核`），供人工抽查。

## 六、未来改进方向

- **交叉验证**：区间引用与同段已校准的金句行号建立关联（同一事件的金句行号修正后，联动修正其附近的区间引用）
- **生成时二次确认**：对高价值行号（章标题、关键事件）做两遍生成交叉比对
- **检索端容错**：行号显示为「行 N（±M 容差）」或直接展示行号附近的原文片段，降低单点误差的影响
