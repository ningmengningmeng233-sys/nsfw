# 成人文学索引（成人文学创意索引 v4.8.5）

> **作者：柠檬才不萌 · 联系：ningmeng2233@qq.com**
>
> 为小说全文建立可检索的创意索引库。通过「元数据 → 索引段落 → 全部索引 → 原文段落」四级路径精确检索定位原文，供写作时提取灵感、桥段、爽点。
>
> 快速开始：`QUICKSTART.md` ｜ 常见问题与排错：`FAQ.md`

---

## 这是什么？

一个 **AI Agent 技能包**，为小说全文建立创意索引库。相当于"小说的搜索引擎"——通读全书，逐章提取关键元素，建立可查询的索引。从此你不用翻几百章去找"那个名场面在哪"、"这句金句在第几章"，也不用凭记忆拼凑伏笔线索。

**双执行器，直调引擎为默认**
- 执行器 1（默认）直调引擎：32 路线程并行直调 LLM，429 限流自动退避重试、
  SQLite 断点层（中断重跑零浪费）、行号双层自动校准（金句 + 区间/短语引用）
- 执行器 2 子代理派发（兼容流程）：INDEX_EXECUTOR=subagent；仅宿主支持 Agent/子代理时可用，否则保持 direct
- 实测：直调单段（5 章）70 秒，500 章小说全书索引约 8 分钟
- **成本预估（v4.6）**：500 章全书 ≈ 150 万 prompt + 200 万 completion token；
  按 DeepSeek 市价（约 ¥1~2/百万 prompt、¥2~8/百万 completion）≈ **¥1.5~5/本**，
  实际以你的 API 定价为准（max_tokens 28000，仅极端长章场景按上限计费）

## 功能特性

| 特性 | 说明 |
| --- | --- |
| 三级降级建索引 | 章节文本按 5 章/段、无章节按 1 万字/段拆分 |
| 直调引擎 | 32 路并行 + 重试退避 + SQLite 断点 + 行号双层校准 |
| 四级检索路径 | 元数据 → 索引段落 → 全部索引 → 原文段落，严格分级节约 tokens |
| 增量追更 | 新章节自动并入；受影响段重跑后必须重新验证，未通过不得刷新导航 |
| 基于索引创作 | 防撞车、桥段复用、续写仿写 |
| 文风蒸馏 | 用索引库材料（金句/创作手法/情绪弧线）直接提炼作者风格卡，续写带笔法；重载场景引用外部 wenfeng-skill |
| 数据外置 | 技能包纯净，用户数据独立存放 |

## 安装（分发）

```powershell
# 1. 安装/运行依赖（推荐使用 uv 临时环境，不污染全局 Python；需要 Python 3.10+）
uv run --with requests --with python-dotenv python -c "import requests, dotenv; print('依赖可用')"
# 使用 tags.custom.yaml 自定义标签时，命令额外加 --with pyyaml（或 pip install -r requirements.txt）
# 若本机已维护项目虚拟环境，也可在该环境中安装：python -m pip install -r requirements.txt
# 注意：运行脚本时始终使用 <技能目录>/scripts/<脚本>.py 的绝对路径，不依赖 cwd。

# 2. 配置 API（任意 OpenAI 兼容 API，如 DeepSeek）
# 在技能目录复制配置模板；Git Bash 可用 cp，PowerShell 可用 Copy-Item
Copy-Item .env.example .env
# 编辑 .env：填入 OPENAI_API_KEY、SUMMARY_API_URL、SUMMARY_API_MODEL

# 3. 配置索引库目录（可选，默认技能目录内 索引库/）
# 在 .env 中设置 INDEX_LIB_DIR=D:\你的索引库目录
```

## 用法

### 拆段

以下命令中的 `<技能目录>` 和 `<索引库>` 使用绝对路径；不要依赖当前工作目录。

```text
# 有章节：默认 5 章/段；无章节：目标约 1 万字符/段，末段允许为剩余短段
uv run --with requests --with python-dotenv python "<技能目录>/scripts/split_segments.py" "<源文件>" --novel 小说名 --author 作者 --lib "<索引库>"

# 分卷源文件（卷内章号独立编号）：加 --volume 卷号，段文件名带卷号防重名丢段
uv run --with requests --with python-dotenv python "<技能目录>/scripts/split_segments.py" "第5卷.txt" --novel 小说名 --author 作者 --lib "<索引库>" --volume 第5卷

# 追更增量：源文件更新后只处理新增章节（不足 5 章并入末段，否则新建段）
uv run --with requests --with python-dotenv python "<技能目录>/scripts/split_segments.py" "<更新后的源文件>" --novel 小说名 --author 作者 --lib "<索引库>" --append
```

### 建索引

```text
# 单段/多段
uv run --with requests --with python-dotenv python "<技能目录>/scripts/build_segment_index.py" "<索引库>/小说原文/XXX-作者/XXX-作者-第1章~第5章-001.md" --lib "<索引库>"

# 整个目录（自动扫描所有段文件）
uv run --with requests --with python-dotenv python "<技能目录>/scripts/build_segment_index.py" "<索引库>/小说原文/XXX-作者/" --lib "<索引库>"

# 断点续传（只跳过 hash 一致且结构合法的索引）
uv run --with requests --with python-dotenv python "<技能目录>/scripts/build_segment_index.py" "<索引库>/小说原文/XXX-作者/" --lib "<索引库>" --skip-existing

# 并发数选择权归用户：默认 32；先确认 API 服务商的并发限制
uv run --with requests --with python-dotenv python "<技能目录>/scripts/build_segment_index.py" "<索引库>/小说原文/XXX-作者/" --lib "<索引库>" --workers 48
```

### 编排器（推荐一站式入口）

`scripts/orchestrate.py` 封装了 SKILL.md 状态机，适合一次完成拆段、建索引、验证、导航。

```text
# 初始化索引库与 .env 模板
uv run --with requests --with python-dotenv python "<技能目录>/scripts/orchestrate.py" --lib "<索引库>" init

# 完整建库：拆段 → 索引 → 验证 → 小说导航
uv run --with requests --with python-dotenv python "<技能目录>/scripts/orchestrate.py" --lib "<索引库>" build --source "<源文件>" --novel 小说名 --author 作者

# 断点续跑 / 删除某书
uv run --with requests --with python-dotenv python "<技能目录>/scripts/orchestrate.py" --lib "<索引库>" resume --workers 32
uv run --with requests --with python-dotenv python "<技能目录>/scripts/orchestrate.py" --lib "<索引库>" delete --novel 小说名 --author 作者 --yes

# 只执行验证门禁 / 查看索引库状态
uv run --with requests --with python-dotenv python "<技能目录>/scripts/orchestrate.py" --lib "<索引库>" verify
uv run --with requests --with python-dotenv python "<技能目录>/scripts/orchestrate.py" --lib "<索引库>" status

# 文风蒸馏（轻量风格卡；需目标作品已建索引）
uv run --with requests --with python-dotenv python "<技能目录>/scripts/orchestrate.py" --lib "<索引库>" style --novel 小说名 --author 作者

# 完整文风蒸馏（可选，配置 INDEX_STYLE_SKILL 后）
uv run --with requests --with python-dotenv python "<技能目录>/scripts/orchestrate.py" --lib "<索引库>" style --novel 小说名 --author 作者 --style-skill "<外部skill入口.py>"
```

### 自定义标签扩展

标签词汇表默认由 `templates/包含元素标签词汇表.md` 提供。如需覆盖内置组或新增流派标签，在**索引库根目录**放置 `tags.custom.yaml`，建索引时自动合并，同名组以自定义为准。

`tags.custom.yaml` 示例（详见项目根目录 `tags.custom.yaml.example`）：

```yaml
# 覆盖内置组
- group: 爽点 · 装逼打脸系
  tags: [装逼打脸, 打脸, 扮猪吃虎, 人前显圣]

# 新增自定义组
- group: 世界观元素 · 赛博朋克
  tags: [赛博朋克, 义体, 黑客, 仿生人]
```

### 行号校准（引擎已自动执行，也可单独跑）

```text
# 金句 + 区间/短语引用双层校准 + 一致性/区间检查（默认索引库相对路径）
uv run --with requests --with python-dotenv python "<技能目录>/scripts/verify_and_fix_lines.py" "<索引库>/章节索引/" --lib "<索引库>"
```

### 行号体检（治理效果复测，ADR-0002）

```text
uv run --with requests --with python-dotenv python "<技能目录>/scripts/check_line_refs.py" --lib "<索引库>" --detail
```

### 检索 / 创作

推荐明确包含“小说索引/索引库/作品名”的请求，例如“在小说索引库里查某剧情在哪一章”。
单独说“续写/仿写/总结/查一下”时，技能会先确认目标作品和范围，不会直接读取原文（见 `SKILL.md` 路由协议）。

## 从旧版本升级

- **v3.33 及更早 → v4.x**：段文件无需重切（格式兼容）；使用绝对路径运行
  `uv run --with requests --with python-dotenv python "<技能目录>/scripts/build_segment_index.py" "<索引库>/小说原文/<小说名>-<作者>/" --lib "<索引库>" --skip-existing`
  ——断点库 `.index_state.db` 启动时自动在线迁移（补 `seg_hash` 列），
  旧 done 记录无内容哈希将按"变更"重新生成（安全策略，非重复消耗）
- 升级后验证：运行 `scripts/_验证批次.py`（结构完整性）+ `scripts/check_line_refs.py`（行号体检）；旧 hash 记录会强制重建安全锚点
- 多卷小说：重建索引时按原卷号传 `--volume` 保持段号一致

## 备份与恢复（v4.6）

索引是逐段直调 LLM 生成的，重建成本 = 每段一次 API 调用 + tokens 费用——**备份的成本远低于重建**。

```text
# 备份：复制整个 <索引库>（三子目录 + .index_state.db）；风格卡另行备份
# Git Bash: cp -R "<索引库>" "D:/索引库备份-YYYYMMDD"
# PowerShell: Copy-Item -Recurse "<索引库>" "D:\索引库备份-YYYYMMDD"

# 恢复后必须重新运行 VERIFY；不能仅凭复制成功声明可用
```

- **建议时机**：每完成一本书的索引备份一次
- 段文件来自你的源 txt——**源文件单独留底**（索引可重建，原文不可再得）
- 风格卡目录（`<INDEX_LIB_DIR>/../风格卡/`）属独立产物，如需保留一并备份

## v1 → v2 变更

- **建索引**：双执行器 —— 直调引擎（默认，16 路并行、429 退避、SQLite 断点、行号校准）与子代理派发（原案，可切换）（注：16 路为 v2 当时值，v3.32 起默认 32 路）
- **性能**：单段 126s → 70s；全书（500 章）3-4 倍提速；token 省约 40%
- **配置**：新增 .env（API key + 索引库路径）；索引库数据外置
- **模板**：新增直调任务模板；子代理任务模板恢复保留（双执行器共用词汇表/章节模板）

## v3.32 变更（2026-08-14，拷问驱动优化）

**性能**：
- 并发默认 16 → 32（DeepSeek 官方并发上限：v4-flash 2500 / v4-pro 500，429 风险≈0）
- `max_tokens` 12000 → 20000（堵长段输出截断，质量底线修复）
- 直调改**流式输出**（SSE 解析，跳过 keep-alive；timeout (30,600) 防大输出超时重试）

**正确性**：
- **段文件内容 hash 检测**：追更改写段文件 → 断点自动失效重跑，防止旧索引行号漂移静默失效
- **token 消耗统计**：usage 记入断点库，跑完打印汇总（总 token/每段均值）

**新脚本**：
- `scripts/split_segments.py`：源文件 → 段文件（5 章/段或 1 万字/段，支持「一章」式省略章号/序章/番外，frontmatter + 校验 + 幂等）
- `scripts/build_novel_index.py`：章节索引 frontmatter → 小说索引骨架（导航表 + 标签聚合 + 总章节数推导）

**模板（章节索引模板.md）**：
- frontmatter 加回「总章节数」（对齐旧版）
- 伏笔小节：「多条伏笔逐条独立列出，各带状态，不得合并」
- 金句小节：「引用一致性规则」——其他小节引用（含行号）的原文必须同步收录金句

**校验（verify_and_fix_lines.py）**：
- 金句引用一致性自动检查（P0-4，规则落地为可执行检查）
- 剧情概要区间重叠 + 章边界连续性检查（P1-6，check-only 不自动改）

## v3.33 变更（2026-08-16，审查驱动修复）

> 版本续号说明：v3.32 之后的下一版曾误标为「v3.9」，v4 起恢复递增（本批修复即原
> v3.9 内容，更正为 v3.33 以便版本序列连续）。

**行号治理（ADR-0002 落地）**：
- 区间/短语引用校准（`fix_range_refs`）：文本指纹回查，唯一命中且不越界才改写，其余保持原样仅统计
- 生成端约束：模板硬性要求第 8 条「行号引用宁缺毋滥」
- 新增 `scripts/check_line_refs.py`：全库行号引用体检（越界 + 章外分档），复测治理效果

**修复（审查发现 + 功能性测试验证）**：
- `verify_and_fix_lines.py`：金句行号修正分支补回右括号（此前修正后括号未闭合，导致该条金句后续不再被正则识别）；金句多命中且原行号不在命中集时跳过不改（与区间校准策略一致，防改错），越界的多命中引用额外加「行号待核」提示；PATTERN 兼容中文弯引号“原文”（中文模型常输出弯引号，此前只认直引号导致整段金句漏校准）；区间正则组1排除右括号（金句结尾「”）」被误截成短语，每段必跳 1 条）
- `build_novel_index.py`：导航排序改为按段编号（此前 basename 字典序把「第10章~」排在「第1章~」前，导致导航乱序、最后索引章节推导错误）
- `build_segment_index.py`：`--no-range` 参数生效（此前直调内嵌路径丢失该开关）；校准改用 `--lib` 指定的索引库（此前内嵌校准固定用 .env 目录，自定义库时静默空转）；流式 usage 统计默认请求（个别 API 不认 `stream_options` 时自动降级重试）；SSE 解析改为字节流手动分割（iter_lines 的 str.splitlines 会把 UTF-8 中文 0x85 字节在 ISO-8859-1 解码后误判为换行，拆断 JSON 行导致「流式响应为空」）；`--skip-existing` 不再抢先跳过 hash 已变化的追更段（此前追更后末段索引过期不重跑）
- `split_segments.py`：新增 `--append` 追更增量模式（不足 5 章并入末段，否则新建段，已有段 hash 不变 → 断点只重跑末段）；字数段名按实际累计字符计算（此前 `--chars-per-seg` 非 10000 时出现「第1万字~第0万字」）
