# 非标准章节处理示例（v4.5）

> 展示当源文件没有标准"第X章"格式时，编排器如何处理（新结构：按字数拆段）。
> v4.5：无章节段文件的索引按字数块划分小节（见 `references/建立索引.md` 1.4）。

---

## 场景一：纯对话体小说

源文件格式：每个对话块用空行分隔，无章节标题。

```
"你来了。"
"嗯，我来了。"
"你不该来的。"
"可我还是来了。"
...
```

### 编排器处理流程

1. **探测章节格式**：用 Grep/Glob 尝试所有正则 → 全部 0 匹配
2. **采样统计字数**：Read（起始行 1，500 行）→ 约 3000 字/500 行
3. **按字数拆段**：目标约 1 万字/段，**段落边界切分**（两个连续换行符之间
   为一段，切点落在段落结束位置，绝不从段落中间硬切），目标约 1 万字符/段，末段允许为剩余短段
4. **命名**：`<小说名>-<作者>-第X万字~第Y万字-NNN.md`
   （原文段）；索引文件同步带 `-idx` 后缀
5. **向用户汇报**：
   ```
   未检测到标准章节格式。已按字数拆段：全书约 45 万字 ÷ 1万字/段 = 45 段。
   目标约 1 万字符/段，末段允许为剩余短段，段落边界切分。
   索引 frontmatter 中将标注「分段方式: 按字数切分」。
   是否继续？
   ```

## 场景二：日期分隔的日记体

源文件格式：
```
2024-01-01
今天天气晴...

2024-01-02
去了一个新地方...
```

### 编排器处理流程

1. 用 Grep 正则 `^\d{4}-\d{2}-\d{2}` 匹配日期行
2. 以日期行作为"章节"边界计算分段
3. 按日期归组：约 1 万字/段或用户指定章数/段
4. frontmatter 标注 `分段方式: 按日期切分`

---

## 场景三：混用多种格式

源文件格式：
```
第1章 开始
...
第二章 继续
...
Chapter 3 转折
...
第4话 高潮
...
```

### 编排器处理流程

1. 用多个正则分别匹配
2. 取**匹配最多**的格式作为主格式
3. 其余标注为"异常章"
4. frontmatter 标注 `分段方式: 混合章节格式，已标注异常章`

## 场景四：卷文件内章号非标准（实战经验）

网文源文件常见形态（大奉打更人实测）：

- **目录文件**：`序章.md` 等可能是"简介+全部章标题"的无正文目录，
  标题数可作全书章数权威参考，但**拆分必须以正文文件为准**
- **卷内独立编号**：每卷从"第一章"重新编号，索引的章节范围需带卷号
  （如"第5卷第86章~第90章"）才能唯一定位
- **第一章标题缺失**：某卷正文第一行直接是内容（无"第一章"标题行），
  第一章边界 = 正文起点（跳过卷首语）
- **番外重新编号**：卷末番外章号从"一"重新计数，与正文章节混淆——
  解析时识别"章号回退"标记番外起点，正文与番外分界明确

处理：摸底阶段逐卷核对标题序列，识别上述异常；拆段时按索引的
"卷+章节范围"从卷文件截取，段文件内行号重新从 1 计数。
